# Security policy

This repository contains public, sanitized hunting examples and supporting schemas. It must not contain secrets, credentials, customer data, private infrastructure, unpublished incident evidence, or production identifiers.

If you find a credential, token, sensitive identifier, unsafe sample, or other material that should not be public, do not open a public issue containing the data. Report the affected path and the minimum context needed to identify it through GitHub's private vulnerability reporting channel when available.

For ordinary query bugs, documentation errors, ATT&CK mapping corrections, or false-positive/tuning issues that contain no sensitive data, a normal GitHub issue or pull request is appropriate.

The security boundary here is information exposure and unsafe public content; these KQL examples are not presented as universal detections and must be validated against local telemetry before production use.
